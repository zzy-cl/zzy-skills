# 文档经营：治理与生命周期

内容之外，文档作为团队资产的运维规则。涉及团队文档治理、文档冲突、历史文档处置时读本篇。

## 权威序：一个主题只有一份正典

同一主题存在多份文档时，读者的实际行为是挑最像官方的那份读——那份往往错得最久。规则：

- 每个主题指定一份 **canonical** 文档，其余要么删除、要么开头一行显式声明被取代（"本文已被 X 取代，保留仅作素材"）。
- 半成品不发进正典：标 WIP 或不落盘——检索不认 WIP 标记，半篇文档会以正式身份误导搜索。
- 新文档取代旧文档时，双向声明：新文头部写"取代 X"，旧文头部加"已被 X 取代"。

## 所有权：有名有姓

- 文档随代码走：**谁拥有模块，谁拥有文档**；交接模块时文档与代码一起交接。
- 无 owner 的文档结局是双输：没人敢改（怕动别人的），没人负责修（腐烂无人认领）。
- 多人协作可以，署名必须单一。

## 写不写：ROI 判断

最贵的杂质是一整篇没人需要的文档。**ROI = 读者次数 × 每次节省的时间 − 持续维护成本。**不配成文的内容：一次性操作、commit message 已完整记录的决策、代码自身可读的逻辑。预期只有自己看的，写进 commit message 就到头了。这与删减共享同一条不对称账本：误删有人问，误留永远付费。

## 答疑回写

文档缺口最准的信号是**重复被问的问题**（阅读量只说明有人来过）。规则：同一个问题第二次口头回答后，必须回写文档——把答疑变成文档的 diff，让答疑投入沉淀而不是蒸发在聊天记录里。配合轻量反馈入口（"本页有误"），让所有读者成为腐烂探测器。

## 与代码注释的边界：引用，不复制

- 注释管**局部与当下**（这一行为什么这么写）；文档管**全局与跨越**（系统怎么运作、怎么接入）。
- 同一件事两边都写详细版 = 腐烂点翻倍。文档引用注释（"why 见 `calculateExRightSlope` 注释"），不复制内容；注释里也不长出小文档。

## AI 时代的两条新现实

1. **AI 是新增读者，且最信任字面**：过期文档会被 AI 用自信的语气转述出去，腐烂传播被乘上系数。可检索性（符号定位）、时效标注（仅限长期真相源文档，见 SKILL.md 第 2 步）、单一正典的价值全部放大。
2. **AI 是新增作者，风险是流畅的错误**：生成文本自带权威语域，绕过人类靠生涩感建立的错误预警。对策：AI 起草 + 人工逐句溯源 + 符号巡检自动化（本技能 `scripts/check_symbols.sh`）。AI 产初稿与候选事实，人做最后的事实裁判。

## 安全边界

内部文档按密级分流：凭证、内网地址、鉴权细节（如 token 生成算法）不进普通 wiki。文档是所有资产里最容易被整体拖走的一类——落笔前过一遍：这篇被外部拿到，泄露了什么。

## 修错的传播阻断

发现一条错误后：对**全部语料** grep 这条说法（一条错误说法散在多份文档里，只改一份等于没改）；在修正处留勘误痕迹（哪里错了、何时核对）；排查错误类型（记忆偏差 / 过度泛化 / 转述失真），针对性加强对应核对动作。
