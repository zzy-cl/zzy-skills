# 教程（how-to）深度指南

## 契约

学习中的读者，一无所知地进来，手把手跟着走。铁律：**保证成功——学习者照做必须得到承诺的结果，任何一步失败都只能归咎于素材（版本、路径、数据），不能归咎于教程漏了步骤。**

## 骨架与要点

```
## 前置条件        —— 环境/版本/权限/账号，逐项可自查（"node ≥ 18：node -v"）
## 目标成果        —— 做完会得到什么，配一张终态截图或输出样例
## 步骤 1..N       —— 编号步骤；每步 = 动作命令 + 预期结果（"此时你应看到 X"）
## 常见问题        —— 报错原文 → 原因 → 处置，按出现概率排序
## 下一步          —— 学完本篇后的合理延伸（1–3 条链接）
```

## 关键规则

1. **每步带验证点**：没有验证点的步骤，读者失败时无从定位是哪一步出的问题。
2. **不解释原理**：教程里塞概念讲解会让读者失去手感——原理是解释文档的事，教程只留一行"为什么需要这步"备注，链接到解释文档。
3. **不留跳转**："参见某文档"是教程之敌——学习者在那里卡死。本篇需要的每条信息要么内联给出，要么明确标注"可先跳过"。
4. **不假设作者环境**：路径、版本、平台差异显式写出；命令可复制执行（一个代码块一条可独立运行的命令）。
5. **实测发布**：教程必须像代码一样做可用性测试——找干净环境从头跑一遍；"显而易见"的那一步恰恰是读者卡死的地方。这次实测同时就是准确性验证。
6. **失败要能回退**：破坏性步骤（删除、迁移、配置覆盖）给出撤销命令。
