# 文件命名

文件名不是内容摘要，是检索键：它只在目录列表被扫读、被搜索命中、被其他文档链接。名字里的每个字符为这三件事服务，其余信息属于 H1 标题或 git。

## 公式

**`主题（领域词）+ 角度.md`**

- 领域词前置：目录排序按前缀聚类，同主题文档天然相邻
- 角度词区分同一主题的不同侧面：本地调试 / 接入指南 / 重构方案 / 踩坑记录
- 长度：主题 2–8 字 + 角度 2–6 字；中文超 15 字，通常是标题或 git 的信息被塞了进来
- 体裁后缀仅在歧义时使用：同一主题出现多体裁才加（「计费退款逻辑札记」vs「计费退款重构方案」）；「调试」已隐含教程、「重构」已隐含方案，角度词能隐含的不加

## 验收测试

1. **排序**：同主题文档在目录列表相邻
2. **搜索**：一年后用领域词 grep 命中
3. **读名知文**：同事只听文件名，能说清文档讲什么、自己要不要读
4. **腐烂**：内容一年后大改，名字依然成立——描述瞬态的名字（「新方案」「重构前」）必烂

## 禁止项

| 规则 | 违反的后果 |
|---|---|
| 不放版本 / 作者 / 最终版 | git 已有；名字里出现两个「最终版」意味着哪个都不是 |
| 仅周期性产物带日期（如周报） | 周期本身是身份（`2026-W37 周报`）；普通文档的日期在 git 里 |
| 不用「临时 / 杂项 / 笔记2」等空词 | 检索永远命中不了；叫「临时」的文档被误删概率最高 |
| 英文一律 kebab-case、无空格 | 空格在 URL 与命令行要转义，链接说断就断 |
| 发布到 Web（docs site / Git 托管页）用英文 kebab-case | 中文 URL 发布后是一串百分号乱码；本机与多数 wiki 可用中文 |

## 组织与标题

- 扁平目录 + 好名字，优于深层文件夹：文件夹藏住重复文档，名字是平铺可搜的；一个主题只有一份正典（见 `doc-governance.md`）
- 文件名是 H1 标题的压缩形态：标题讲完整故事，文件名保留领域词、去掉冗余（标题「行情套餐详情页本地开发调试」→ 文件名「行情套餐详情页本地调试」）——两者不必逐字一致，领域词必须都在
