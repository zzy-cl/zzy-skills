# 反模式清单与好坏对照

重写、评审、压缩文档前先读本篇。每条反模式都有真实语料出处——它们全部在某次文档评审中被实际抓到过。

## 结构反模式

| 反模式 | 症状 | 后果 | 处置 |
|---|---|---|---|
| 编号 + 三级嵌套 | 4.1–4.4 式目录 | 层级掩盖体裁混装，导航决策翻倍 | 两级封顶；装不下拆文档 |
| 平行重复节 | "一条推送的完整旅程"把机制章重讲一遍 | 同一事实多个腐烂点，修错必漏 | 一件事只说一次，说在离动作最近处 |
| 均匀并列无主干 | 九个一级节（概念/铁律/场景/调试/限制）平级 | 读者分不清主干与补充 | 机制归机制节，补充嵌位或删除 |
| 孤儿标题 | 两三行内容撑起一节 | 目录虚胖 | 并入兄弟节 |
| 尾部杂物抽屉 | "附：文件索引/名词速查/函数速查表" | 静态索引保证过期，误检率高 | 删除；归宿是 ADR 与代码注释 |
| 文艺标题 | "锚点的一生""斜率怎么算" | 不可检索、不合专业语域 | 名词短语 + 领域术语（"锚点生命周期""斜率递推"） |

## 内容反模式

| 反模式 | 症状 | 处置 |
|---|---|---|
| 代码复读 | 把 deps 序列化、Symbol 过滤等代码逻辑翻译成文字 | 删——读代码十秒能恢复，写了必然腐烂 |
| 无后果的参数罗列 | token 生成方式、version 字符串、仅日志用的映射 | 删——除非造成过坑 |
| 装饰性图表 | 把一行文字画成 mermaid（"A → B → C"流程图） | 删——一行文字能说清的不画；确需流程/生命周期图时用 Mermaid，且每条边承载结构 |
| 过度泛化的规则 | 早期数据恰合规律被总结成铁律（"奇订偶退"——实际协议号 44 打破） | 对到源头证伪；规则必须带成立条件 |
| 离题漂移 | WS 文档坑清单里混进 HTTP 接口版本问题 | 坑的准入标准：挂在读者在本体系内的哪个动作上 |
| 行号定位 | "见 hooks.ts:351" | 改「文件 + 符号名」，行号会腐烂 |
| 导出噪音 | `***` 分隔线满屏、`&#x20;` 实体、断掉的加粗 | 作者没有以读者身份重读过——重读并清理 |
| 均匀加粗 | 每个 bullet 都有加粗关键词 | 加粗预算只给不变量与后果 |
| 因果脑补 | 为参数编造听起来合理的 why（未与作者/代码核对） | 参数级 why 留在常量定义处；不写无出处的因果 |

## 好坏对照（可直接套用）

| 反例 | 正例 |
|---|---|
| `## 影线：为什么最高价不能直接加增量` | `## 影线处理` |
| `每笔推送先问锚点"这单你能接吗"` | `每笔推送先校验锚点可用性` |
| `减号两边是两台不同的"计算器"` | `减号两侧分属两套复权口径` |
| `心跳 20s（服务端 60s 断连取 1/3）` 写进流程正文 | 该 why 留在心跳常量定义的代码注释里 |
| 解说句："收发不对称是全体系的核心约束" | 流程块并排展示：订阅时"按 symbols[] 拆成多个 channel"，推送时"按 channel 路由回所有订阅者" |
| 独立"铁律与坑"一节列七条 | 频道铁律写进"新增协议要改 msgHandlerMap"那一步 |
| 文末函数速查表（带行号） | 正文用符号名定位，检索交给 IDE |
